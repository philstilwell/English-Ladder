# English Ladder student portal

The student portal is a separate Cloudflare Worker, `englishladder-students`, in the existing Cloudflare account. It serves the student subdomains without changing the public lesson site's Worker or publishing schedule. The first registered address is `kh26.englishladder.com`.

The portal provides login, private dated session feedback, an overall ESL assessment, session summaries, a session sidebar, and a mobile session picker. Each session has a bookmarkable `#feedback/YYYY-MM-DD-HHMM` address; the time suffix allows multiple sessions on one day. The newest feedback opens after login. The `#assessments` page shows strengths, recurring patterns, and next priorities with links to the relevant session feedback. Accounts without an assessment show an empty state. Teacher access is clearly labeled.

## Account addresses

Use the student's initials followed by the last two digits of the year the account is created, for example `ab26`. Keep that address permanently; do not recalculate it in January. If an address is already assigned, explicitly choose a distinct suffix before registering another account. Never overwrite an existing student to resolve a collision.

Each active registered subdomain points to the same Worker. A proxied wildcard DNS record and Worker route make new addresses available automatically. The www host has a more-specific route exclusion and remains on the public lesson site. The explicit original student and administrator custom domains remain in wrangler.jsonc. Add and manage accounts from phil.englishladder.com; a deployment is no longer needed for each account. The universal teacher credential works on every configured account; a teacher signs in separately on each subdomain. No public student directory is exposed.

## Runtime secrets

Provision these through Cloudflare's encrypted Worker secrets. Do not commit actual names, passwords, signing keys, `.dev.vars`, or provisioning inputs:

- `STUDENT_ACCOUNTS`: JSON object keyed by student ID, each with first-name-only `name`, optional chosen `nickname`, and `password` string properties. The API also reduces legacy full-name records to their first word before responding.
- `TEACHER_PASSWORD`: the universal teacher password, also used for the administrator page.
- `STUDENT_PASSWORD`: the default shared password for newly registered accounts. Legacy per-account passwords in STUDENT_ACCOUNTS continue to work.
- `SESSION_SECRET`: at least 32 characters of cryptographically random signing material.
- `STUDENT_PASSWORD_PEPPER`: a separate, stable random secret of at least 32 characters used for custom student password verification. Provision before enabling assignment. Rotating this secret requires assigning new custom passwords; rotating SESSION_SECRET does not.
- `STUDENT_PASSWORD_ENCRYPTION_KEY`: a separate random 256-bit key encoded as 64 hexadecimal characters. Provision before assigning recoverable passwords. Keep it in Worker secrets, never in Git or public assets. Rotating or losing it prevents reading existing encrypted copies; migrate them under the old key before rotation. Password verification and student sessions do not depend on this key.

Passwords are lowercased in the browser and again on the server, including teacher passwords. Spaces are significant. Passwords are never embedded in the public bundle. Shared and teacher passwords are encrypted Cloudflare secrets verified with a keyed, constant-time HMAC comparison. Personal passwords assigned on administrator account pages override the shared/legacy password for that student. Authentication uses a salted PBKDF2-SHA256 verifier, protected by HMAC with STUDENT_PASSWORD_PEPPER and bound to the directory record key. PBKDF2 uses the Workers Web Crypto limit of 100,000 iterations; the independent pepper remains outside the database. Verification uses Web Crypto constant-time HMAC verification. At the owner's explicit request, the private directory also stores a recoverable AES-256-GCM copy for the administrator login-details view. Every copy uses a random 96-bit nonce and authenticated data binding the account key and current verifier. The separate encryption key stays outside the database. See [Cloudflare Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/) and [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Sessions use an eight-hour, signed, host-only `HttpOnly; Secure; SameSite=Strict` cookie. The session is bound to both the student ID and exact host. Changing an account password invalidates that account's student sessions; changing the teacher password invalidates teacher sessions; rotating `SESSION_SECRET` invalidates every session. Sign-out removes this browser's cookie. There is no server-side session registry, so sign-out does not revoke a previously copied token; it expires or is invalidated by credential rotation.

Login permits five attempts per student/IP per minute and twenty per student per minute using Cloudflare rate-limit bindings. These limits are local to each Cloudflare location and are not a globally exact lockout. Unknown accounts and unconfigured Workers fail closed. Requests that change sign-in state require an exact same-origin header. No student information is returned before login. All responses disable caching and indexing, and the portal loads no analytics or third-party scripts.

## Private session storage

Historical lesson sets can be imported with `POST /api/learning-import` on the student's host. This requires a teacher session and the exact same origin. The request contains reviewed `feedback`, a complete `assessment`, per-session `quizzes` with timestamped evidence, and `priorAssessment` for the account version that was reviewed. Each source must belong to the same account or arrive in the same import. The server validates the entire set before saving it in one transaction, archives the quizzes and prior assessment privately, and preserves all student attempts. Identical retries are idempotent; conflicting existing records or a changed assessment are rejected. An older import cannot replace a newer current assessment. No raw transcript or nickname evidence is accepted in this learning-record payload. This manual import makes no AI calls and does not change the nightly schedule or its generation limits.

`FEEDBACK_STORE` binds the `FeedbackStore` Durable Object class, using a private SQLite database for each student. The Worker selects the database from the registered account hostname after checking the signed session. The database has no public URL. The `feedback-v1` migration creates the SQLite-backed namespace. Never remove or rename this migration or class to reset a deployment; that can affect stored records.

`GET /api/feedback` returns up to 100 newest session entries with a `nextCursor`; pass `?before=<cursor>` for older entries. `GET /api/feedback/<id>` returns a session. Both require login. `PUT /api/feedback/<id>` requires the teacher role and exact same origin, validates a maximum 64 KiB JSON body, and atomically updates the record and its index. Repeating a PUT replaces that session, without duplicates. There is no deletion endpoint. Both student and teacher responses omit Zoom note identifiers, and neither view links to Zoom meeting notes. All responses prohibit caching. The browser stores no records persistently and clears private content on sign-out, expiry, and restoration from the browser's page cache.

`GET /api/assessment` returns `{ assessment: <record or null> }` for the authenticated account. `PUT /api/assessment` has the same teacher, origin, size, and privacy restrictions as feedback publishing. It replaces the current assessment at the private key `assessment:current`. Editors can include `priorAssessment` to require an exact match with the current record; a conflicting edit returns 409 and preserves the current record. A successful conditional edit archives the prior assessment privately. Each assessment source must already exist in this student's feedback storage with a reviewed full transcript; every timestamp must fall inside that transcript's recorded coverage. Assessment evidence links show dates only and lead to internal feedback pages. Elapsed transcript times and coverage ranges stay in stored evidence but are not displayed on student pages. No raw transcript or source-note link is exposed.

`PATCH /api/feedback/<id>` repairs practice only, with the same teacher, exact-origin, and 64 KiB restrictions. Send `{practice, priorFeedback}`, where `priorFeedback` is the current public detail response (without its private note ID). An atomic comparison rejects stale edits with 409. Successful edits privately archive the old practice and preserve every other field, the session index, assessment, and quiz attempts. Extra top-level fields are rejected. Full publication and practice repairs reject exercises that repeat teaching or vocabulary examples, allowing target phrases to recur in genuinely new examples. Authors and reviewers must also check for trivial rewrites that a text comparison cannot detect.

Follow [AGENTS.md](AGENTS.md) for every student's feedback. The `scope: "esl"` value and transcript metadata are required, but they do not replace a human/agent content review. Read full available transcripts, separate teacher feedback from extra practice, use first names, and omit unrelated personal conversation. New exercises are clearly labeled. Show both New York and Japan dates to avoid confusion across midnight.

Write student-facing content at an A1–A2 reading register: short sentences, common words, and simple examples. This does not assign a proficiency level to the student. Put words and phrases being discussed in quotation marks or italics. Vocabulary headings and practice models are italicized by the page; authors must mark target words in prose and distinguish lesson quotations from new examples. These preferences are saved in the portal's AGENTS.md for future pages.

Keep authoring inputs under ignored `student-portal/private/`, with directory permission 700 and file permission 600. Actual records, transcripts, and credentials must never enter Git, public assets, or browser storage. `tests/fixture.mjs` shows the schema with fictional data. Source transcript offsets and segment counts document the available coverage; raw transcripts are not stored on the portal.

New eligible nightly lessons now retain a privately reviewed, anonymized transcript for up to three calendar months. Names and identifying details are replaced while Student/Instructor/other-speaker roles, timestamps, and non-redacted wording stay intact. Pending retries reuse this server copy when its source and speaker mapping are unchanged. Internal cache endpoints are not browser APIs. Nightly cleanup removes all expired versions, including for paused accounts and with publishing disabled or Zoom disconnected; a failure is shown in the administrator's nightly status. Assessments, CEFR evidence, feedback, and quiz history remain. See [QUIZ_AUTOMATION.md](QUIZ_AUTOMATION.md#private-transcript-cache-and-retention) for privacy limits, source refresh, cost, and retention boundaries. Deployment does not import old transcripts or run paid inference.

Publish a reviewed JSON array using `node student-portal/publish-feedback.mjs <student-origin> <private-file>`. Supply the existing teacher password on standard input through a private pipe or a terminal with echo disabled, never as a command argument. The publisher validates all records before connecting, verifies teacher access, uploads each record, compares every saved record with its input, and signs out. It supports HTTPS student subdomains and HTTP localhost for development. The SQLite-backed service is available on Cloudflare's free plan; this small text library is expected to remain within included quotas. See [Cloudflare pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/).

The public lesson site's existing local completion markers are separate from this portal and do not transfer automatically.

An assessment may include an optional private `quiz` with a title, simple instructions, and seven multiple-choice questions. The storage format still accepts up to ten questions so older quizzes and saved attempts remain readable; nightly authoring requires exactly seven. Each question references one assessment pattern by `patternIndex`, provides two to four distinct options with individual feedback, identifies `correctIndex`, and includes a correct model sentence. The same teacher-only assessment publisher validates and saves it. Older assessments without a quiz continue to work.

The `#quiz` page shows one question at a time with immediate feedback, retries, and a first-try result. Its introduction shows only plain source lesson dates, without links. Answer instructions appear next to the question. These are new practice questions based on the assessment, not transcript quotations. The Quiz menu entry stays hidden until a quiz is available. If lesson evidence is insufficient, leave the optional quiz absent; no arbitrary session-count threshold is imposed. New quizzes are created by the nightly server job; see [QUIZ_AUTOMATION.md](QUIZ_AUTOMATION.md). It reads full Zoom transcripts and private first-try history. A quiz may have its own `sourceSessions`, `patternTitles`, and `generatedForSession`, allowing a later lesson without changing the earlier assessment. Quiz sources must exist in the same private account with reviewed transcripts. Legacy quizzes inherit assessment sources and pattern titles. The workflow helper exports complete history and merges a new quiz into the live assessment.

Student answers save after each choice in the same private per-student database. The first choice is append-only; later choices do not change the first-try score. A completed attempt is marked when the last question is answered correctly. Reloading or signing back in resumes the saved attempt, and starting again creates a new attempt only on its first answer. One unfinished attempt is shared across tabs/devices. Teacher practice is labeled and never writes student results. Earlier in-memory quizzes cannot be recovered.

`GET /api/quiz/state` resumes an unfinished attempt; after completion, it offers a newer published quiz automatically. Without a newer quiz, it returns the completed result. `?new=1` offers a fresh quiz only after the previous attempt is complete. `POST /api/quiz/answer` accepts only an attempt UUID, quiz version, question index, and choice index (maximum 1 KiB). It requires a student session and exact same origin. A transaction validates question order and appends the choice, using server timestamps and server-calculated summary scores. Identical retries are idempotent, so a lost response cannot duplicate an attempt or change its first answer. Conflicting tabs reload the saved state. Failed saves block further answers until retried or reloaded and are never labeled as saved. There are no update/delete endpoints for history.

Each active account’s administrator edit page links to the teacher-only `#quiz-results` page, which shows dated attempts, first-try mistakes, original answer choices, later retries, and progress bars grouped by matching question sets. `GET /api/quiz/results` returns 20 newest summaries with a `nextCursor`; pass `?before=<cursor>` for earlier attempts. `GET /api/quiz/results/<uuid>` returns the full saved attempt. Each attempt snapshots the quiz, pattern titles, and source lesson references, so changing an assessment cannot reinterpret earlier results. Unfinished attempts remain visible and are excluded from completed-score trends. Dates use New York time.

No answers are stored in browser persistent storage. Private page state clears on sign-out or expiry, while saved server records remain available. This is learning practice, not a secure exam or proficiency score: authenticated students can see answer keys, and repeated exposure affects scores. Tests cover private access, roles, account isolation, ordering, invalid answers, concurrent tabs, duplicate requests, version snapshots, pagination, save failure, resuming, teacher preview, plain source dates, seven-question authoring, and logout cleanup.

Publish a reviewed assessment JSON object with `node student-portal/publish-feedback.mjs <student-origin> <private-file> --assessment`, supplying the teacher password privately on standard input as above. Publish its source session records first. Use the full transcripts to identify repeated patterns, include successful uses and evidence of progress, and distinguish future practice targets from measured performance. Do not infer a formal proficiency level or pronunciation score from transcript text.

### Administrator CEFR estimates

The administrator menu also includes **Technical notes** at `/#technical-notes`. It is a read-only reference for CEFR rules, transcript privacy and retention, Zoom/cache behavior, nightly timing, quizzes, accounts, and spending safeguards. Its non-sensitive content contains no student records or credentials. Keep the page and its revision date aligned with implementation changes. The reference uses the existing authenticated administrator view and supports direct navigation, mobile layout, and sign-out.

The private student list includes **CEFR estimate**. Open an account for the level/range, confidence, latest lesson date, rationale, vocabulary/structure range, grammar control, connected ideas, conversation skills, and expandable timestamped learner examples. CEFR means Common European Framework of Reference for Languages. These are provisional AI-assisted estimates of transcript-observable conversation, not comprehensive or certified CEFR results. Pronunciation, pace, independent listening, reading, and writing are not assessed. Teacher judgment remains important.

The first estimate waits for two distinct usable anonymized transcripts and uses the latest two. After that, reviews run no sooner than one calendar month after the previous review (Eastern calendar date, with month-end clamping), using the latest four available retained sessions. If only two or three remain, use those; fewer than two defers the review. No review repeats on unchanged evidence. Nightly checks can perform a due monthly review without a new lesson or a Zoom connection. Paused accounts are excluded. Only private saved sources within the three-month retention window count; no historical import is triggered.

CEFR has a separate author/editor pair of model calls. Every selected transcript is supplied in full, and each session must have an exact verified Student quotation. Instructor/other-speaker turns are context only. Previous estimates, old quotes outside the window, assessment prose, and quiz results are not inputs. Low confidence is required for two lessons; moderate confidence requires at least three and is not automatic. Only identical or adjacent A1–C2 bands are accepted. A too-large window, failed review, or changed source never produces a partial estimate. Failed or insufficient monthly reviews retain the earlier level. Daily feedback and quiz publication cannot overwrite CEFR.

`GET /api/admin/cefr-status` returns pages of 20 minimal summaries. `GET /api/admin/students/:key/cefr` returns the current explanation/examples and a safe scheduling summary, including the next eligible review date. Both require the administrator host's teacher session. Student-host cookies and student APIs cannot read them. The per-student store keeps `cefr:current`, `cefr:review` (completion date and source references), and dated `cefr:history:<date>:<windowHash>` records separately from assessments and quiz attempts; legacy history remains. The internal monthly publisher rechecks source selection, date eligibility, quote grounding, and retention inside its write transaction. Account deletion removes all these records too. The browser clears details on navigation, sign-out and session expiry and discards delayed responses.

Estimated CEFR cost is $0.02–$0.10 per review before allowances at the October 15, 2026 published model rates. One attempt per UTC day and two attempts per calendar month per student bound retries. This separate allowance does not consume the existing two-per-day/twelve-per-month ordinary lesson allowance. Tests mock all AI/Zoom calls; deployment itself makes no paid inference call.

The descriptor reference is the [Council of Europe spoken-language table](https://www.coe.int/en/web/common-european-framework-reference-languages/table-3-cefr-3.3-common-reference-levels-qualitative-aspects-of-spoken-language-use). The rubric in `cefr.mjs` is a brief adaptation for this limited teaching use, not a validated CEFR examination. Evidence counts are teaching safeguards, not official CEFR thresholds.
