# Student feedback rules

- Write all student-facing assessments, feedback, summaries, headings, and practice instructions in short, clear English suitable for A1–A2 readers. Use common words and one idea per sentence. Explain necessary grammar terms with a simple example. This is a reading-register preference, not a claim about a student's assessed level. Keep the tone respectful and adult. Harder vocabulary being taught may remain, with an easy explanation.
- Put words and phrases being discussed inside quotation marks or italics, including in headings and practice instructions. For example: “Phil showed two ways to use ‘access’.” Clearly distinguish actual lesson quotations from new practice examples; never turn a paraphrase or new example into a claimed transcript quote.
- Use only a student's first name in prose. An explicitly chosen nickname may be used as a profile label. Never display or publish full names.
- Every student's session feedback must focus exclusively on English as a second language: usage, vocabulary, grammar, comprehension, conversational skills, and language practice. Do not summarize or evaluate personal lives, work performance, beliefs, health, or unrelated conversation topics.
- Find every matching session in the requested period, including known display-name variants. Read the complete available transcript for each session, not just Zoom's generated summary. Record its coverage and identify missing transcripts honestly.
- Ground feedback in timestamped learner utterances and teacher exchanges. Distinguish explicit in-session teaching from additional practice. Treat automatic transcription errors cautiously; do not infer pronunciation quality or proficiency scores from text.
- Explain language accurately even when a conversational explanation in the source was oversimplified. Label new model sentences and exercises as practice rather than transcript quotations. Keep quoted examples brief and remove unnecessary personal details.
- Store actual student feedback only in the private per-student server storage. Keep publishing inputs in the ignored private directory with restrictive file permissions. Never commit student records, raw transcripts, credentials, or provisioning inputs; never place them in public assets or browser storage.
- Test account isolation, authentication, teacher-only writes, logout cleanup, and mobile access whenever changing record handling. Use fictional records in tests.
- Overall assessments follow the same ESL-only and privacy rules. Support recurring patterns with references across the full transcripts, balance them with successful uses, and label practice targets as goals rather than current scores. Link to private feedback pages, never Zoom meeting notes.
- Quizzes should practice patterns from the student's assessment with simple instructions and feedback after each choice. Label quiz items as new practice, use quotation marks or italics for the English being taught, and do not present quiz results as a proficiency level. Keep authored quizzes in private student storage and clear in-memory attempts on sign-out or expiry.
- Save student quiz choices privately after each answer. Preserve the original first choice, source lesson references, and question wording for each attempt. Teacher previews must never count as student attempts. Show first-try mistakes and dated progress only to the authenticated teacher; do not treat practice scores as a proficiency level. Name and link the source lessons on the student quiz.
- Show the Quiz menu item only when a reviewed quiz is available. If there is not enough lesson evidence to author one, omit the quiz and its menu entry instead of inventing questions or showing an empty tab.
- When automatic quizzes have been requested, follow QUIZ_AUTOMATION.md. Read each new full transcript and the saved original first choices from earlier attempts. Publish one short quiz per eligible completed session, with simple instructions and choice-by-choice feedback. For the authorized nightly page updates, refresh the assessment with new evidence and preserve its earlier version privately. Always preserve saved attempts. Keep scheduling checkpoints private; do not invent mistakes when no results exist.
