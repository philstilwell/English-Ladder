A reviewer changed {sender} to a translated variable name, which the runtime does not recognize. The English source was previously assembled from separate fragments. Tester Noura and engineer Alex need a complete localizable message, intact named arguments, and checks using long names and item labels.
Language workshop: A fluent sentence can still break the runtime contract

Emi: Use build number 420 and ja-JP. Start the shield tutorial, equip the shield, and open its action prompt.

Emi: That resource reuse may explain the context problem, but the actual resource history still needs checking.

Emi: I will compare expected behavior with the displayed target text and record the tested package.
Sam: Good. The ticket can describe the exact meaning problem without guessing which person introduced it.
Emi: Yes. The context screenshot and steps give us a clear shared reference for the fix.

Dialogue 02: A fluent sentence can still break the runtime contract
Original fictional setting: A fictional gift notification has named placeholders {sender} and {item}. The approved target-language sentence places the item before the sender. A reviewer changed {sender} to a translated variable name, which the runtime does not recognize. The English source was previously assembled from separate fragments. Tester Noura and engineer Alex need a complete localizable message, intact named arguments, and checks using long names and item labels.
Professional roles: Alex / Noura
Published dialogue (reference script, not my own performance):
Alex: The revised sentence reads naturally according to the reviewer, but the notification now shows an unresolved token.
Noura: The placeholder for the sender was renamed during translation. The runtime still supplies the original identifier.
Alex: Does preserving that identifier mean we also have to keep the sender at the start of the sentence?
Noura: No. The named argument must remain intact, but its position can follow the target sentence structure.
Alex: In this approved wording, the item appears before the sender. Our old implementation joins several English fragments.
Noura: That string concatenation is the structural problem. Give the translator the full message and its intended meaning.
Alex: I can expose one message with the two arguments instead of expecting every language to use the same fragment sequence.
Noura: Good. The word order can then change without changing which value each argument represents.
Alex: Are the argument values already display text, or should the translation alter their grammatical form?
Noura: We need that contract documented. Inflection is not something we can safely invent for arbitrary names and item labels.
Alex: I will describe the value types and provide examples so the reviewer knows what can appear in each slot.
Noura: Add a translator instruction identifying the protected arguments and the relationship the message must express.
Alex: The resource also includes presentation tags. A reviewer thought one tag was an English word that needed translation.
Noura: Then validate token integrity for both arguments and markup, using the actual resource schema.
Alex: The editor preview looks correct after my change. Is that enough to send it for final review?
Noura: Run a round-trip test through export and import, then inspect the built notification with realistic values.
Alex: I will include a long sender name and a multiword item label instead of testing only A and B.
Noura: That tests interpolation and gives the language reviewer a meaningful sentence to inspect.
Alex: If the formatter rejects the pattern, I will report the syntax error separately from the wording question.
Noura: Exactly. A parser error needs engineering evidence; a language concern needs its own contextual explanation. Test both in the target build.
Vocabulary in this exchange: placeholder: Token replaced by a runtime value. / named argument: Runtime value referenced by a stable name. / interpolation: Insertion of values into a message pattern. / string concatenation: Joining fragments to form text. / word order: Arrangement of words and phrases in a sentence. / inflection: Change in word form expressing grammatical information.
