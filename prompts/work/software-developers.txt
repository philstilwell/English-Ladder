Lesson 02: Debugging from reproducible evidence
Original fictional case: A fictional import fails on a three-row file containing an empty date field. A two-row file without that row succeeds. The stack trace points to date parsing, but no controlled test has isolated the empty field as the cause.
Language workshop: Separate a clue from a cause
Communication goal: Explain a debugging hypothesis and propose evidence that distinguishes it.
Language guidance: A stack trace shows a path associated with failure, not necessarily the original cause. When two examples differ in several ways, identify the confounding differences before claiming that one field explains the failure.
Useful frames (complete the gaps with case facts): The failure occurs with ___, but ___ also differs. / The trace points to ___; that does not yet establish ___. / A comparison holding ___ constant would help distinguish ___.
Vocabulary: reproduction: A documented set of conditions and actions that produces an observed software behavior again. / stack trace: A record of function calls associated with a point in execution, often captured when an error occurs. / hypothesis: A proposed explanation for observed behavior that can be investigated against evidence. / minimal example: A reduced input or program that retains the behavior being investigated while removing irrelevant detail.
Speaking task: Prepare for two minutes. Speak for 45-60 seconds using the case facts, then respond to your partner's question. Switch roles and repeat without reading the model response.
Partner: Developer receiving the bug: ask which inputs and conditions differ between the passing and failing examples.
Guided response task: Complete a workplace dialogue by selecting one of four supplied options. Compare the feedback and say the completed exchange aloud. Do not write an open-ended message.
Optional second-round challenge: The same failing file succeeds once after a retry. Explain why one success does not establish a fix.
Model for comparison AFTER my attempt, not a response to give me first: The failing three-row file contains an empty date, and the stack trace reaches date parsing. Those observations make the empty field a useful hypothesis, not yet a demonstrated cause. Could we compare otherwise identical examples with and without that value? The smaller passing file also changed the row count, so it does not isolate the field.
