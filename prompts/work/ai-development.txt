Original fictional case: A document assistant displays the wrong refund deadline. Retrieval returned the current policy, which states 30 days, but the generated answer says 60. The interface displays the generated text unchanged. Priya owns the model integration; Alex manages the product. A demonstration is scheduled for Friday. No cause has been confirmed, and Alex cannot approve a production release alone.
Language workshop: The answer is wrong, but which layer failed?
Communication goal: Distinguish components and ask a diagnostic question without assigning blame.
Language guidance: A trace records events; a diagnosis explains them. A wrong answer identifies a symptom, not automatically a model defect. Keep retrieval output, model output, and displayed text separate.
Useful expressions (preserve the supplied facts): Which component first shows the wrong value? / The retrieved passage says 30 days; the generated answer says 60. / That locates the mismatch, but it does not establish the cause. / Can you attach the request ID and the redacted trace? / Product approval and technical diagnosis are different decisions. / Can we reproduce it with the same payload and configuration? / By "the AI," do you mean the model or the whole application? / I will send the evidence and name the unresolved question. / Does the interface display the response without changing it? / Let us inspect the boundary before assigning ownership. / Change one component while keeping the others fixed. / We have an observation, not a verified root cause. / Does this test depend on the policy index being current? / Please retain the configuration used for that request. / I can commit to an update, not to a fix by that time. / The demonstration remains scheduled; release approval is separate.
Vocabulary: application stack: The components that together deliver an application. / retrieval: Finding source material relevant to a request. / language model: A model that processes and generates language sequences. / user interface: The part of a system a user sees and operates. / orchestration: Coordination of model, retrieval, and tool steps. / inference: Running a trained model to produce an output. / endpoint: An address through which a service accepts requests. / payload: The data carried in a request or response. / trace: A linked record of events in a request's path. / dependency: A component or condition another part relies on. / upstream: Earlier in the relevant processing path. / downstream: Later in the relevant processing path. / symptom: An observed sign of a problem, not its cause. / root cause: The underlying cause established by investigation. / reproduction: Recreating a reported result under stated conditions. / request ID: An identifier used to locate a particular request. / schema: A defined structure for data and its fields. / tool call: A model-requested invocation of an available tool. / API: Application programming interface; a defined software interaction boundary. / contract: Agreed expectations between software components. / integration: Connecting components into a working system. / observability: The ability to infer system behavior from available signals. / triage: Initial assessment that determines priority and ownership. / handoff: Transfer of work and its relevant context.
Speaking task: Check the dialogue, then read the 30-day source and 60-day generated answer as separate observations. Locate the mismatch before assigning its cause. Switch roles. Ask for D-184, the redacted trace and the request configuration; retain the Thursday findings update without promising a fix. Complete the citation-link exchange. State that the generated response contains the citation while the interface omits it, then hand over the exact request.
Partner: Priya: AI integration engineer / Alex: Product manager
Guided response task: Select supplied answers for the dialogue gaps. Check the explanations, then read the completed exchange aloud; no original writing is required.
Optional second-round challenge: A support assistant generates a correct answer with a citation ID. The interface omits the citation link. The display team needs the exact recorded request, not an assumption that retrieval failed.
Model for comparison AFTER my attempt, not a response to give me first: Alex: All right. I will describe the customer-visible problem and keep the demonstration decision separate. What should your update include for that decision?
Priya: The reproduction result, affected cases, remaining uncertainty, and a proposed next step. I will preserve the configuration so the comparison is meaningful.
Alex: That works. Please send it by three on Thursday, even if the investigation is incomplete. I will confirm who can decide about Friday.
Priya: Agreed. The handoff will say what we know, what we do not know, and which decision still needs an owner.

Lesson 02: LLMs, Transformers, Tokens, and Context
Original fictional case: A document-summary request reserves 4,000 output tokens. Its instructions and documents contain 29,000 input tokens. The configured total context limit is 32,000 tokens, and the request is rejected before generation. Lina proposes increasing the output allowance. Omar owns the request configuration. The team must retain the exception clauses; no larger-context model has been evaluated for this task.
Language workshop: A larger answer will not make the input fit
Communication goal: Correct a technical misconception tactfully and negotiate a bounded alternative.
